## Risks
- The biggest risk to this plan is scope creep in the opposite direction this session already avoided once: treating "it has a sidebar link to /revenue" as license to go build a full accounting module. Every phase above is written to modernize/harden the **existing** shell; the ERP build-out stays parked until Rasim decides.
- Vulnerability count (71 via container audit / 163 per GitHub's own count) is real but currently low-impact in practice, since almost nothing in the app does I/O yet — don't let that create false confidence; clear them in Phase 6 regardless of current low exploitability.
