# Architecture

## What this is today
BizFlow is a single-page Next.js 15 (App Router) application generated by Firebase Studio. The entire UI lives in one file, `src/app/page.tsx`: a shadcn/ui `Sidebar` shell wrapping a `Dashboard` component that statically renders three cards (revenue/expense logging forms, an appointment calendar). There is no routing beyond `/` — the sidebar links to `/calendar`, `/revenue`, `/expenses` with no matching route files, so those links 404.

## Layers
- **Presentation**: `src/app/`, `src/components/ui/*` (shadcn/ui primitives, generated — not hand-written business UI), `src/components/icons.ts`.
- **"Service"**: `src/services/calendar.ts` — one function, hardcoded return value. Not a real service layer yet.
- **AI**: `src/ai/ai-instance.ts` (Genkit + Google AI client, model `googleai/gemini-2.0-flash`, reads `GOOGLE_GENAI_API_KEY` from env — correctly not hardcoded), `src/ai/flows/suggest-transaction-category.ts` (one complete flow, unused by the UI).
- **Persistence**: none. `firebase` is a direct dependency but has no initialization or call site anywhere in `src/`.

## Why no Clean/Hexagonal/DDD treatment yet
Per the Phase 8 applicability table (`PROMPT.md`), Hexagonal/Clean architecture earns its place when "external systems need swapping" and DDD when "real domain complexity and invariants" exist. Today there is exactly one real external integration (the Genkit AI flow) and zero persisted domain data — there's no boundary to protect yet and no invariant to model. Introducing ports/adapters or aggregates now would be speculative layering over three UI cards, which KISS/YAGNI explicitly override (decision 7). This should be revisited **if and only if** the ERP build-out (see `docs/REPOSITORY_AUDIT.md` and `projects/info/state/APPROVALS.md`) is approved — at that point a real persistence boundary (Firestore today, something else tomorrow) would justify a port/adapter around it.

## Deployment topology
None today — no Dockerfile, no CI, no hosting config beyond what Firebase Studio's own preview environment implies (not represented in this repo). Phase 5 establishes the first real container baseline.
