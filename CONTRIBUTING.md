# Contributing to BizFlow

## Branching and commits
- Branch naming: `phase-<n>/<topic>`, cut from `preview` (never from `main` directly).
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat`, `fix`, `refactor`, `perf`, `test`, `build`, `ci`, `docs`, `chore`, `revert`; `!`/`BREAKING CHANGE:` footer when applicable). One logical change per commit.
- PR titles are also Conventional Commit titles. One PR per logical unit of work.

## Local setup
- This project is Docker-first: everything is built, tested, and run in containers — never with a host-installed `node`/`npm`.
- `make verify` (build + test stage) must be green before opening a PR. `make up` only starts the app after `make verify` passes.
- `make shell` drops into the dev container for interactive debugging.

## Secret scanning
This repo ships a local pre-commit hook at `.githooks/pre-commit` that runs [gitleaks](https://github.com/gitleaks/gitleaks) against staged changes. Enable it once per clone:

```sh
git config core.hooksPath .githooks
```

If gitleaks isn't installed locally the hook warns instead of blocking — the CI secret-scan job is the authoritative gate.

## Reporting bugs / requesting features
Use the issue templates under `.github/ISSUE_TEMPLATE/`. Never include real secrets, tokens, or `.env` contents in an issue — redact them first.

## Review process
One PR per phase/topic per repo. Maintainers merge only after `make verify` is green in CI. Never `--no-verify`.

## AI-attribution policy
No commit, PR title, PR description, or comment in this repository may carry an AI co-author trailer (e.g. `Co-Authored-By: Claude ...`, `Claude-Session: ...`) or any "generated by/with AI" marker. Authorship is the maintainer's alone.
